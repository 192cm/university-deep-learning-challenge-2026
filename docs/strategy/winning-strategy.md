## 1. 결론 먼저

### 1.1 권장 파이프라인


## 2. 현재 상황 진단

### 2.1 시간이 가장 희소한 자원이다

남은 11일 중 GPU를 실제로 돌릴 수 있는 시간은 그보다 짧다. 따라서 **"이론적으로 최선"이 아니라 "11일 안에 끝나고 실패해도 롤백되는" 순서**로 배치해야 한다. 아래 우선순위는 전부 이 제약에서 나온다.

### 2.2 이미 실패한 경로 (반복하지 말 것)

저장소 이력상 **유료 API teacher로 verified-CoT를 만드는 시도가 3회 모두 실패**했다.

| 시도 | 결과 |
|---|---|
| `phase2_verified_cot_luna_budget5_v1` | `blocked_quality_gate`, 생성 0행 |
| `phase2_verified_cot_luna_3k_final_v1_v3` | eligible 12,209행 전부 `unprocessed`, 채택 0행 |
| `phase2_v4_final_v1_terra` | `reject_for_quality_audit_and_main` — "어떤 effort 설정도 게이트를 통과하지 못함", 채택 0행 |

누적 지출 약 **$4.6**, 산출 SFT 행 수 **0**. 하드 예산 상한이 $4.5인 상태에서 12,000문제 teacher 증류는 애초에 재정적으로 불가능하다.

> **결론: 유료 teacher 증류는 완전히 폐기하고, teacher를 base 모델 자신으로 교체한다(RFT).** 이것이 Qwen2.5-Math에서 가져올 핵심 아이디어이며, 비용이 0이고 규칙상 안전하며(로컬 생성·정답 라벨 자동 검증), 품질 게이트를 우리가 직접 통제한다.

### 2.3 저장소 전면 초기화 (2026-08-19, 의도된 결정)

`scripts/`, `configs/`, `tests/`, `artifacts/`, 모든 파생 데이터, `README.md`, `AGENTS.md`를 작업 트리에서 제거했다. **남은 것은 대회 원본 데이터 4종과 `docs/`뿐이다.**

근거는 명확하다. 기존 코드베이스는 Phase 0~2의 6단계 검증·manifest·provenance 레이어를 두르고 있었는데, 그 레이어가 실제로 만들어낸 SFT 데이터는 **0행**이었다(2.2). 남은 11일에 필요한 것은 검증 인프라가 아니라 **RFT 생성 → SFT → 추론** 세 경로다.

전면 초기화가 실제로 잃은 것은 생각보다 적다. 사라진 파생 산출물은 대부분 **CPU 수 분~수 시간이면 원본에서 재생성**되고(2.4), 유일하게 비용이 큰 GPU 산출물이었던 Phase 1 베이스라인은 **git HEAD(`601ae48`)에 그대로 남아 있어** 이 문서 3장의 실측치가 여전히 검증 가능하다. 즉 **측정 결과는 보존되고 코드만 새로 쓰는** 상태이며, 이는 정확히 의도한 바다.

> 커밋 전까지는 `git show HEAD:<path>`로 이전 산출물을 언제든 열람할 수 있다. 초기화를 커밋하더라도 `601ae48`에 영구 보존되므로, 3장 실측치의 감사 경로는 끊기지 않는다.

새 코드베이스의 최소 구성은 다음 6개면 충분하다. 그 이상은 만들지 않는다.

| 모듈 | 역할 |
|---|---|
| `src/extract.py` | 답 추출·정규화 (계산 금지, 순수 문자열 처리) |
| `src/generate.py` | 배치 생성 (greedy / 샘플링 / k 지정) |
| `src/evaluate.py` | holdout 지표 (greedy, pass@k, maj@k, agreement, invalid rate) |
| `src/build_rft.py` | 생성물 → 정답 일치 필터 → SFT jsonl |
| `src/train_sft.py` | QLoRA SFT |
| `src/submit.py` | 추론 → `submission.csv` (행 수·ID·정수 검증 포함) |

각 스크립트는 config JSON 하나와 seed를 받고, 출력 디렉터리에 `manifest.json`(입력 SHA-256, config SHA-256, seed, 환경, 지표)을 남긴다. **manifest는 이 한 겹만 유지한다** — 재현 의무를 만족하는 최소치이고, 그 이상은 지난 3주가 증명했듯 산출물을 늦춘다.

### 2.4 남은 원본 4종과 재구축 계획

작업 트리에 남은 파일은 다음이 전부다(직접 확인).

| 파일 | 행 수 | 열 | 성격 |
|---|---:|---|---|
| `data/deep_chal_math_train.csv` | 17,000 | `id`, `question`, `answer` | 대회 원본 |
| `data/deep_chal_math_leaderboard.csv` | 1,000 | `id`, `question`, **`" answer"`** | 대회 원본 (answer 전량 공란) |
| `data/train_filtered_ids.csv` | 627 | `id`, `answer`, `question` | 대회 측 훈련 제외 목록 |
| `data/deep_chal_math_leaderboard_filtered.csv` | 831 | `id`, `question` | 리더보드 169행 제외본 |

> **함정 하나를 미리 박아둔다.** `deep_chal_math_leaderboard.csv`의 세 번째 열 이름은 `answer`가 아니라 **앞에 공백이 붙은 `" answer"`** 다. 제출 코드가 컬럼명을 하드코딩하면 최종일에 조용히 깨진다. 모든 CSV 로딩은 **헤더를 strip한 뒤** 다루고, 제출 파일의 컬럼명은 sample submission에서 읽어 그대로 따른다(8.1).

**canonical train은 이제 더 깨끗하게 정의된다.**

```text
canonical = deep_chal_math_train.csv (17,000)  −  train_filtered_ids.csv (627)  =  16,373행
```

이전 canonical은 16,359행(= 17,000 − 627 − 자체 검토 14)이었다. 그 14행 원장은 초기화로 사라졌지만 **되살릴 필요가 없다.** 새 정의는 **대회 제공 파일 두 개에만 의존**하므로 제3자가 한 줄로 재현할 수 있고, 재현 의무 관점에서 오히려 개선이다. 14행 차이는 전체의 0.09%로 어떤 결론도 바꾸지 않는다(3장 통계를 16,373행으로 재계산해 확인함).

**대회 측 627행 제외 목록의 성격 (2026-08-20 재검증).** 먼저 구조를 확인했다. 627개 ID는 **전부 원본 17,000행에 존재**하고(누락 0), `answer` 열은 627행 모두 원본과 **동일**하며(차이 0건), `question` 차이 352건은 **전량 공백·개행 정규화**다. 즉 이 파일은 정정본이 아니라 **순수한 제외 목록**이고, 위의 뺄셈 정의가 성립한다. 리더보드 1,000행과의 질문 일치·템플릿 일치도 **0건**이므로 오염 제거 목적도 아니다.

결함 표지별로 분해하면 다음과 같다.

| 표지 | 행 수 |
|---|---:|
| 이미지 / URL / `[asy]` 의존 | 174 (27.8%) |
| 그림 참조 (이미지 링크는 없음) | 149 |
| 빈칸 placeholder만 | 34 |
| **표지 없음** | **270 (43.1%)** |

**원본의 이미지·URL 의존 문항 216개 중 174개(80.6%)를 제거**하는 것은 맞지만, 그것이 이 목록의 전부는 아니다. 표지 없는 270행을 직접 열어 보면 이미지 문제가 아니라 **텍스트 파손·라벨 오류**다.

- `train-000189` — `(n + 5)(n - 5)(n-15) 7$?`. 부등호가 통째로 유실된 파손 문항
- `train-000222` — 질문 전문이 "Defeated number solution.", `answer=0`
- `train-000176` — 제약식이 중복 서술되어 답 `0`이 성립하지 않음

> **따라서 이 목록은 이미지 필터가 아니라 "이미지 + 파손 텍스트 + 신뢰 불가 라벨" 필터다.** 여기서 나오는 결론은 하나다. **canonical 16,373에도 같은 계열의 파손·오답 행이 남아 있을 개연성이 높고, 그 비율을 우리는 아직 모른다.**

**그렇다고 자체 필터 정책을 새로 설계하지는 않는다.** 파손 문항과 오답 라벨을 사람 눈이나 휴리스틱 규칙으로 잡아내는 작업은 지난 3주가 증명했듯 시간부터 삼킨다. 대신 **RFT 생성 자체를 필터로 쓴다.** 문항별 정답 일치 샘플 수 `c`가 그대로 라벨 신뢰도의 대리 지표가 되므로, 별도 비용 없이 의심 문항이 분리된다(5.2). 사람의 판단이 개입하지 않아 재현도 가능하다.

사전 제외는 표지가 확실한 것 하나뿐이다: **canonical에 남은 이미지·URL 문항 42개는 SFT 대상에서 무조건 뺀다.**

**재구축 대상과 비용**

| 산출물 | 방법 | 비용 |
|---|---|---:|
| canonical train 16,373행 | 원본 − 627 | 수 초 |
| holdout 4종 (random / template / hard / format) | 고정 seed 재생성 | 수 분 |
| RFT pool | canonical − holdout 전체 ID | 수 초 |
| answer-only 대조군 | canonical → `FINAL_ANSWER: <answer>` | 수 초 |
| **OpenMathInstruct-2 정수 부분집합** | HF 스트리밍 → 정수 답 필터 → 오염 검사 | **수 시간 (CPU)** |

앞의 4종은 D0 오전이면 끝난다. 유일하게 무거운 것이 OMI2인데, **이것은 GPU를 쓰지 않는다.** 따라서 D2-3의 RFT 생성이 GPU를 점유하는 동안 **CPU에서 병렬로 돌리면 일정 비용이 0이다**(7장). 이전 실적상 5만 행을 스트리밍하면 정수 답 39,450행(78.9%)이 남았으므로, 필요한 1.5만 행은 넉넉히 확보된다.

**잃은 것 중 유일하게 아쉬운 것은 holdout의 동일성이다.** 새 split은 seed가 달라 이전 것과 구성이 다르므로, 3.4의 실측치(62.5% 등)는 **새 split에서 ±2pp 수준으로 재현될 뿐 정확히 일치하지 않는다.** D0의 합격 기준을 "일치"가 아니라 "**60~65% 범위 진입**"으로 잡는 이유다. 이후 모든 비교는 새 split 기준으로 통일한다.

## 3. 우리 데이터가 실제로 말해주는 것

### 3.1 문제 분포 (실측)

| 항목 | canonical train (16,373) | leaderboard (1,000) |
|---|---:|---:|
| 질문 길이 중앙값 / p99 | 201자 / 757자 | 206자 / 753자 |
| LaTeX(`$`) 포함 | 44.2% | 46.9% |
| 기하 키워드 | 9.9% | 12.0% |
| 정수론 키워드 | 6.8% | 8.1% |
| 조합·확률 키워드 | 2.9% | 3.2% |
| 이미지·URL·`[asy]` 의존 | 0.3% (42행) | 1.0% (10행) |

**집계 정의 (재현용).** 이전 판의 키워드 값(기하 6.4% / 정수론 8.0% / 조합·확률 2.0%)은 정의 스크립트가 2.3의 초기화로 사라져 재현이 불가능했다. 아래 정의로 재계산해 대체한다. 어떤 키워드 집합을 쓰든 결론은 바뀌지 않지만, **재현 의무상 정의가 문서에 남아 있어야 한다.**

- 대상 문자열: `question` 열을 **소문자화**한 원문. 부분 문자열 포함이면 1회만 계수(문항 단위, 중복 계수 없음).
- 기하: `triangle` `circle` `angle` `polygon` `square` `rectangle` `sphere` `cylinder` `trapez` `quadrilateral` `perimeter` `radius` `diagonal` `hexagon` `parallelogram`
- 정수론: `prime` `divisor` `modulo` `remainder` `divisible` `gcd` `lcm` `congruen` `factorial` `multiple of`
- 조합·확률: `probability` `permutation` `combination` `how many ways` `expected value` `choose` `arrangement`
- 이미지·URL: `http://` `https://` `[asy]` `.png` `.jpg` `.jpeg` `.gif` (대소문자 무시)
- 길이: 문자 수 기준. **p99는 nearest-rank** (`sorted[ceil(0.99n) - 1]`). 보간식 percentile을 쓰면 ±5자 정도 달라진다.

> 3.4의 문제 유형별 정확도(기하 30.7% 등)는 **보존된 Phase 1 artifact 자체의 분류 체계**를 따르며 위 키워드 정의와 다르다. 두 수치를 같은 축으로 비교하지 말 것.

**train과 leaderboard의 분포는 사실상 동일하다.** 리더보드가 기하·정수론에서 2pp 남짓 높지만 방향과 폭 모두 이전 판과 같고, 결론을 바꾸지 않는다. 따라서 holdout 성능은 리더보드 성능의 신뢰할 만한 대리 지표다. 이 점이 아래 모든 의사결정의 전제다.

### 3.2 정답 분포 (실측, canonical train)

- 비정수 정답 **0개** (전부 정수)
- `|answer| <= 100`: **70.1%** / `<= 1000`: 88.3%
- 음수 **486개**, 0 **210개**
- 최대 절댓값 3,431,577,212,128,939 (10자리 초과 정답 20개)

따라서 답 추출기는 **음수·0·10자리 이상 대정수**를 반드시 정확히 처리해야 한다. 이 세 경우가 `format` diagnostic set의 존재 이유다.

### 3.3 템플릿 암기는 통하지 않는다 (실측)

숫자를 `#`으로 정규화해 비교한 결과:

- leaderboard 1,000문제 중 train과 **완전 일치: 0개**
- 숫자만 다른 동일 템플릿: **17개 (1.7%)**
- train 내부 중복 템플릿: 121그룹 / 266행 (1.6%)

> **결론: retrieval·template 암기 전략은 최대 1.7%가 상한이다. 완전히 폐기한다.** (규칙상으로도 test-time retrieval은 회색지대다.) 대신 이 수치는 **template-group holdout이 random holdout과 거의 같은 값을 주는 이유**를 설명해 준다(실측 62.5% vs 63.6%). 즉 우리 holdout은 누수 없이 신뢰할 수 있다.

문제 유형별 B0 greedy (random scope): 산술 문장제 **70.9%**, 조합·확률 43.1%, 정수론 41.0%, 대수 39.2%, 기하 **30.7%**.

여기서 읽어야 할 네 가지:

4. **invalid_output_rate 14.7%가 가장 싸고 큰 손실이다.** 3.5 참조.

## 4. 후보 1 — AIMO 대회에서 무엇을 가져올까

### 4.1 AIMO에서 **가져올 수 없는 것**

AIMO Progress Prize 1 우승(NuminaMath-7B-TIR)의 실제 구조는 다음과 같았다.

- Stage 1: CoT SFT → MATH 56.3%
- Stage 2: **TIR(코드 실행) SFT → MATH 68.2% (+11.9pp)**
- 추론: 문제당 후보 48개 + 코드 실행 피드백 깊이 4 + 다수결(SC-TIR) → 50문제 중 29문제 정답

즉 **우승의 결정적 상승분이 전부 Python 실행에서 나왔다.** 본 대회는 2026-08-01 운영진 답변으로 추론 중 코드 실행·도구 호출을 명시적으로 금지한다. AIMO-2 우승(OpenMath-Nemotron-14B) 역시 170만 건의 TIR 해답이 핵심이고, 베이스 모델 크기(14B)와 데이터 규모(54만 문제 / 320만 해답)가 우리 제약 밖이다.

> **AIMO 해법을 "따라 하는" 접근은 본 대회에서 구조적으로 불가능하다.** 이것을 먼저 인정해야 남은 시간을 낭비하지 않는다.

### 4.2 AIMO에서 **가져올 것 3가지**

**(1) test-time compute를 아끼지 않는다**

NuminaMath는 문제당 48샘플을 뽑았다. 우리 실측에서도 maj@3만으로 +3.1pp다. 본 대회는 1,000문제 × 24시간이고 4090에서 greedy 1,000문제가 약 600초이므로, **k=16이면 약 2.7시간, k=32여도 5.4시간**이다. 추론 예산은 병목이 아니다.

**(2) GenSelect (AIMO-2) — 본 대회에서 합법적으로 쓸 수 있는 최고의 아이디어**

후보 64개를 뽑고, 그중 16개씩의 요약을 모델에게 보여주며 "가장 타당한 것을 고르라"고 학습시킨 뒤, 이를 반복해 선택된 답들에 다시 다수결을 적용하는 방식이다. AIMO-2 보고에 따르면 다수결 baseline을 유의하게 상회하며, **개선폭이 적은 생성 수(fewer generations)에서 더 크다.** (단, 저자들은 최종 Kaggle 우승 파이프라인에 GenSelect를 포함하지 않았다.)

**본 대회 규칙 적합성 — 운영진 답변으로 확인됨.** 운영진은 금지의 근거를 다음과 같이 밝혔다.

> "추론 과정에서 외부 코드 실행이나 도구 호출이 개입될 경우, 구현 형태가 매우 다양할 뿐 아니라 해당 기능이 실제로 학습을 통해 모델에 내재화된 것인지를 검증하기도 어렵다고 운영진이 판단하였습니다. 따라서 추론(inference) 시에는 모델의 추론 출력만으로 답을 도출하는 것을 원칙으로 하며, 코드 실행 및 도구 호출은 허용하지 않습니다. **Majority Voting, Self-Consistency 등 다중 샘플링 기반의 test-time 기법은 자유롭게 활용**하실 수 있으니 참고 부탁드립니다."

이 답변은 금지선을 **"외부 코드 실행·도구 호출"**에 긋고, **"다중 샘플링 기반 test-time 기법"** 범주 전체를 자유 사용으로 열어 둔다("Majority Voting, Self-Consistency **등**"). GenSelect는 정확히 이 범주 안에 있다.

- 코드 실행·외부 도구 없음 → 금지 사유에 해당하지 않음
- 외부 모델 호출 없음 (동일 가중치, 프롬프트만 다름)
- 후보 생성과 선택이 **전부 모델의 추론 출력**으로 이루어짐 → "모델의 추론 출력만으로 답을 도출" 원칙과 정면으로 부합
- 다중 샘플링 기반 test-time 기법 → "자유롭게 활용" 대상

**남는 제약은 규칙이 아니라 우리 쪽 설계 규율 하나다.** 별도 어댑터를 로드하면 "다른 외부 모델을 호출해 앙상블" 조항의 해석 위험이 생기므로, **하나의 어댑터가 풀이 모드와 선택 모드를 모두 수행하도록 SFT 믹스에 함께 넣는다**(6.4). 이 조건만 지키면 GenSelect는 규칙 문제 없이 쓸 수 있다.

**(3) 엔지니어링 규율**

NuminaMath 팀이 실패한 것들도 그대로 참고 가치가 있다. RLOO 기반 RL은 "학습 곡선은 좋았으나 성능 이득 없음", 모델 머지(DARE/TIES/WARP)는 "유의한 퇴행", 더 큰 모델은 타임아웃이었다. **RL과 머지에 마지막 주를 태우지 않는다.**

## 5. 후보 2 — Qwen2.5-Math에서 무엇을 가져올까

### 5.1 가져올 수 없는 것

Qwen2.5-Math의 self-improvement는 3층 구조다.

1. **pre-training 데이터 합성** — 본 대회는 사전 학습 자체가 금지
2. **post-training: Qwen2.5-Math-RM-72B로 rejection sampling + GRPO** — 72B RM 학습 불가, 별도 RM 모델은 "다른 모델 사용·앙상블" 해석 위험
3. **inference: RM으로 best-of-N 유도** — 위와 동일

또한 Qwen2.5-Math 자체를 베이스로 쓰는 것은 규칙상 **명시적으로 금지**되어 있다. 우리가 참고할 수 있는 것은 **설계 사고방식뿐**이다.

### 5.2 가져올 것 3가지

**(1) rejection sampling으로 SFT 데이터를 스스로 만든다 — 이번 개정의 핵심**

Qwen2.5-Math의 SFT 데이터는 "모델이 대량 샘플링 → 정답 일치 + RM 점수 상위만 채택"으로 만들어진다. 우리는 RM이 없지만 **정답 라벨이 있으므로 exact match 자체가 완벽한 검증기**다. RM 없이도 rejection sampling의 핵심을 그대로 재현할 수 있다.

RFT 계열의 일반적 관찰: 자기 생성 정답 CoT로 학습하면 일반 SFT 대비 일관되게 향상되고, 그 폭은 **문항당 서로 다른 정답 추론 경로 수에 대략 로그-선형**이며, **성능이 낮은 모델일수록 이득이 크다**(LLaMA-7B GSM8K 35.9% → 49.3%). 3B 모델에 유리한 조건이다.

**(2) 2라운드 self-improvement 루프**

Qwen2.5-Math는 "더 강한 SFT 모델 → 더 나은 RM → 다음 라운드 데이터"를 반복한다. 11일 안에서는 **정확히 2라운드**만 돈다.

- R1: base로 k=16 샘플 → 정답 일치분 채택 → SFT-v1
- R2: SFT-v1로 **R1에서 0/16이었던 문제에만** k=32 재샘플 → 채택분 추가 → SFT-v2

R2는 base가 못 풀던 문제를 커버하므로 데이터 난이도 분포가 개선된다. (예상 추가 수확: 실패 약 2,200문제 중 15~25%)

> **2026-08-22 갱신 — 이 루프는 2라운드까지 가지 않는다.** T6·T6-1이 모두 채택 실패로 끝나 SFT-v1이 존재하지 않는다.
> (T6 본안 -0.48pp/p=0.449, T6-1 A +0.27pp/p=0.679·format -3.91pp, T6-1 B -8.30pp. 채택 모델은 T4 base로 유지.)
> SFT-v1이 없으면 R2는 같은 base로 다시 뽑는 것이라 self-improvement가 아니고, 기대 수확도 pass@48 − pass@16 의
> 꼬리 확률뿐이다. 위의 "15~25%"는 개선된 SFT-v1을 전제로 한 숫자이므로 지금은 성립하지 않는다.
> 따라서 **R2는 아래 라벨 신뢰도 판정(의심 집합) 전용으로 축소하고, SFT-v2 학습은 실행하지 않는다.**
> 남은 GPU 예산은 6장 [C] self-consistency·[D] GenSelect로 옮긴다 (pass@32 86.3% vs greedy 68.0%, 방치된 헤드룸 약 18pp).
> 실행 세부는 execution-prompts.md 의 T7 절을 따른다.

**여기에 라벨 신뢰도 판정을 겹친다 (2.4에서 나온 요구사항).**

exact match를 검증기로 쓰는 이상, **라벨이 틀린 문항에서는 검증기도 틀린다.** 실패 양상이 둘인데 위험도가 전혀 다르다.

| 양상 | 결과 | 위험 |
|---|---|---|
| (a) 맞는 풀이가 전부 기각 | 그 문항에서 데이터가 안 나옴 | 낮음 — 수확 손실뿐 |
| (b) **틀린 풀이가 틀린 라벨과 우연히 일치** | **오답 풀이가 SFT에 채택됨** | **높음 — 학습을 오염시킴** |

문항별 정답 일치 샘플 수 `c`는 RFT 과정에서 이미 계산되므로, 이를 라벨 신뢰도 대리 지표로 쓰면 **추가 비용 0으로** 두 양상을 모두 막는다.

| `c` (R1 16샘플 기준) | 처리 |
|---|---|
| `c >= 2` | 정상 채택. 문항당 최대 2~4개 (6.2) |
| `c == 1` | 채택하되 **1개만**. 우연 일치((b)) 위험 구간 |
| `c == 0` | R2 대상 |

- **R2는 재수확인 동시에 파손·오답 탐침이다.** R1+R2를 합쳐 **0/48인 문항은 `의심 집합`으로 영구 분리한다.** 다만 이 집합은 채택 풀이가 0개이므로 **RFT 경로에서는 이미 자동으로 빠져 있다.** "SFT에서 제외한다"는 말은 실행 관점에서 아무 일도 하지 않는다. 규칙이 실제로 무는 곳은 둘뿐이다.
  - **추가 샘플링 예산을 더 쓰지 않는다.** 안 풀리는 문제에 compute를 더 붓는 것이 기본 반응이지만, 이 집합의 상당 부분은 **애초에 풀 수 없는 문항**이다.
  - **answer-only 대조군(6.2)에는 이들이 그대로 들어간다.** 그쪽은 라벨을 타겟으로 직접 쓰므로 오답 라벨을 그대로 학습한다. 대조군 범위는 바꾸지 않되(RFT pool 동일 유지) **ablation 슬라이드에 이 비대칭을 각주로 명시한다** — 우리 결론에 유리한 방향의 교란이므로 숨기면 안 된다.
- **의심 집합의 크기를 반드시 기록한다.** canonical에 남은 파손·오답 비율의 **하한 추정치**이며, 2.4가 열어 둔 "그 비율을 모른다"에 처음으로 숫자를 붙이는 유일한 값싼 수단이다. 발표 자료에도 그대로 쓴다(9장).
- **holdout에는 이 규칙을 적용하지 않는다.** holdout은 고정이고, 오답 라벨이 섞여 있다면 그것은 **리더보드에도 같은 비율로 섞여 있다.** 즉 우리 지표의 천장이 100%가 아닐 뿐이며, holdout을 청소하면 리더보드 대리 지표로서의 성질이 오히려 깨진다. 청소하지 않고, 천장이 낮다는 사실만 인지한다.

**(3) "선택도 학습 대상"이라는 관점**

Qwen2.5-Math의 RM@N > maj@N 관찰은 AIMO-2 GenSelect와 같은 결론이다. 우리는 별도 RM 대신 **GenSelect로 이 이득을 규칙 안에서 구현**한다.

## 6. 권장 전략 — 레버 4개

### 6.1 [A] 출력 계약 수리 (최우선, 0.5일)

**근거: 3.5.** 수학 실력을 전혀 안 올리고 얻는 점수다.

- `max_new_tokens` **1024 → 2048.** 상한 도달 건의 97%가 0점이고, hard scope는 상한 도달률이 21%다.
- **다단계 fallback 추출기** 확정: `FINAL_ANSWER:` → `\boxed{}` → 마지막 줄 단독 정수 → 본문 최후 정수.
  - 규칙 준수: 추출기는 **모델이 이미 출력한 문자열을 읽고 표기만 정규화**한다. 새 계산·방정식 풀이·수식 평가를 절대 하지 않는다.
  - 정규화 대상: 천단위 콤마, 전각 기호, 후행 마침표·단위, `+` 부호, `−`(U+2212) → `-`.

- **빈 답 금지.** 어떤 경우에도 정수 하나를 남긴다(최후 fallback `0`). 빈 값은 무조건 오답이므로 찍는 편이 항상 낫다.

**검증 기준**: `format` split invalid rate < 3%, random split invalid rate < 5%.

### 6.2 [B] verified-CoT QLoRA SFT (핵심, 4일)

**데이터 믹스**

| 소스 | 규모 | 역할 |
|---|---:|---|
| RFT R1 (자기 생성, 정답 일치) | ~10,000 | 대회 분포 정합 — **주력** |
| OpenMathInstruct-2 정수 부분집합 (D2-3 CPU 병렬 재구축) | 15,000 샘플링 | 일반 수학 추론 + 형식 안정화 |

- 외부 데이터는 **원본 leaderboard 1,000문항 전체**와 exact / 숫자 정규화 / 근접 중복 오염 검사를 통과해야 한다. 831행 필터본을 기준으로 하면 169문항이 검사에서 빠진다.
- 한 문제당 채택 풀이는 **최대 2~4개**로 제한한다. 쉬운 문제가 데이터를 지배하는 것을 막기 위함이며, RFT 이득이 "서로 다른 추론 경로 수"에 로그-선형이라는 관찰과 맞물린다. 단 `c == 1`인 문항은 **1개만** 채택한다(5.2의 라벨 신뢰도 규칙).
- **SFT 입력에서 명시적으로 제외하는 것은 하나뿐**: canonical에 남은 이미지·URL 문항 **42개**(2.4). 0/48 의심 집합은 채택 풀이가 0개라 자동으로 빠지므로 별도 제외 로직이 필요 없다 — 단 **규모는 반드시 기록한다**(5.2). 둘 다 holdout에서는 제외하지 않는다.
- **answer-only 대조군은 RFT pool 전체 범위를 유지한다.** 그 결과 이 대조군만 오답 라벨을 그대로 학습하게 되는데, CoT 쪽에 유리한 교란이므로 ablation 표에 각주로 명시한다(9장).
- 채택 풀이 중 **가장 짧은 것 우선.** 3.5에서 본 대로 출력 길이는 그 자체로 위험 요인이다.

**학습 설정 (4090 24GB 기준 출발점)**

| 항목 | 값 |
|---|---|
| 방식 | QLoRA 4-bit NF4 |
| LoRA rank / alpha | 64 / 128 |
| target modules | attention + MLP projection 전체 |
| seq len | 2048 |
| epoch | 2 |
| LR | 1e-4, cosine, warmup 0.03 |
| loss | assistant 토큰만 |
| 출력 형식 | 마지막 줄 정확히 `FINAL_ANSWER: <integer>` |

**필수 대조군 (발표 평가에도 그대로 쓰인다)**

1. base (학습 없음)
2. answer-only SFT (canonical → `FINAL_ANSWER: <answer>`, RFT pool과 동일 범위) — CoT의 가치를 증명하는 대조군
3. 외부 CoT만
4. RFT만
5. RFT + 외부 CoT (본안)

한 번에 변수 하나만 바꾼다. 2번 대조군은 **"CoT 학습이 실제로 필요했다"를 수치로 보여주는 유일한 증거**이므로 반드시 돌린다.

### 6.3 [C] adaptive self-consistency (1.5일)

- SFT 모델로 T=0.7~0.8, top_p=0.9~0.95, **k=16** 기본.

### 6.4 [D] GenSelect (2일, 규칙상 허용 확인됨)

운영진 답변으로 "다중 샘플링 기반 test-time 기법 자유 사용"이 확인되었으므로(4.2), 이 레버는 **조건부가 아니라 계획된 단계**다. 우리 실측에서 pass@3와 maj@3 사이에 5.4pp가 방치되어 있고 k를 키우면 격차가 더 벌어지므로, 남은 레버 중 상한이 가장 명확하다.

- 학습 데이터: RFT 과정에서 이미 생긴 **정답 풀이 + 오답 풀이**를 그대로 재활용한다. **추가 생성 비용이 0**이라는 점이 이 레버의 최대 장점이다 — [B]를 수행하면 [D]의 데이터가 부산물로 딸려 나온다.
- **난이도 층화가 이 데이터의 핵심이다.** GenSelect가 회수하는 격차는 정답이 후보 중 소수인 문항에만 있다. `c>=13` 문항은 다수결이 이미 맞히므로 학습해봐야 "다수 쪽을 고르라"만 배운다. 그런데 R1 pool은 `c=13~16`이 71.9%라 그대로 뽑으면 헛돈다(T6를 무효로 만든 난이도 역상관과 같은 실패). 우선순위: **T7 R2 수확분(정답 1~2/48)** > `c=1~3`(1,211문항) > `c=4~7`(918문항) > `c>=8`은 형식 앵커로 20% 이내.
- 포맷: `문제 + 후보 풀이 요약 N개(N=8~16)` → `짧은 판단 근거 → 선택한 후보 번호 → 최종 답`. (근거를 먼저 쓰게 하는 이유는 출력 붕괴 방지다. 아래 갱신 각주 참조.)
- 추론: 후보 16개 생성 → GenSelect 4~8회 반복 → 선택된 답들에 다수결. (AIMO-2는 64후보에서 16개씩 뽑아 64회 반복 후 다수결을 적용했다. 우리 예산에 맞춰 축소한 형태다.)
- ~~**동일 어댑터가 풀이 모드와 선택 모드를 모두 처리하도록 SFT 믹스에 함께 학습한다.** 별도 어댑터를 로드하면 "다른 모델 앙상블" 해석 위험이 생긴다. 이것이 유일하게 남은 제약이다.~~
  > **2026-08-22 갱신 — 이 제약을 완화한다.** 규칙 문언을 다시 확인했다. 금지 조항은 "다른 외부 모델을 호출해 앙상블"이고 LoRA·QLoRA는 허용 학습 기법으로 명시되어 있다([rules.md](../information/rules.md)). 금지 대상은 다른 베이스 모델이지 허용된 base 하나에 얹은 어댑터가 아니다.
  > 따라서 **선택 전용 LoRA 어댑터를 따로 학습한다.** 풀이 패스는 T4 base(어댑터 없음), 선택 패스는 같은 base + 선택 어댑터다. base 가중치는 한 벌이고 병합하지 않으며, manifest에 base revision 해시와 어댑터 해시를 나란히 기록한다.
  > 두 모드를 한 어댑터에 넣지 않는 이유는 그러면 풀이 패스가 rft_r1_v2 어댑터로 바뀌기 때문이다. T6-1 A가 Δ+0.27pp/p=0.679·format -3.91pp로 게이트를 못 넘겼으므로, 이미 기각선에 걸린 모델을 채택하는 셈이 된다. 선택 모드만 학습하면 풀이 성능은 base 그대로다.
  > 출력이 "후보 번호"만으로 붕괴하는 것(T6-2 answer-only의 실패 모드)을 막기 위해 타깃을 `짧은 판단 근거 → 후보 번호 → 최종 답` 순서로 고정하고, 후보 순서 셔플 일치율로 위치 암기를 검사한다.
- **무학습 few-shot 대조군을 함께 잰다.** 같은 base에 선택 프롬프트만 넣은 경로를 동일 예산에서 평가한다. 추가 학습 0회·생성 1회로 끝나며, "선택 모드는 학습이 필요했다"를 수치로 말할 수 있게 된다.
- 채택 기준: holdout에서 **동일 k 예산의 maj@k를 상회하고, 무학습 few-shot 대조군도 상회할 때만** 채택한다. 둘 중 하나라도 못 넘기면 어댑터를 버리고 더 나은 쪽(few-shot 또는 [C])으로 되돌린다.

### 6.5 명시적으로 **하지 않을 것**

| 항목 | 이유 |
|---|---|
| TIR / Program-of-Thought / SymPy·solver | 운영진이 명시적으로 금지 (2026-08-01) |
| test-time BM25·embedding retrieval | 회색지대이며, 실측 템플릿 중복 1.7%로 이득 자체가 없음 |
| 별도 reward model / 두 번째 어댑터 앙상블 | "다른 모델 사용·앙상블" 해석 위험 |
| 유료 API teacher 증류 재시도 | 3회 실패, $4.6 소진, 산출 0행 (2.2) |
| full fine-tuning | 24GB에서 3B full FT는 시간·메모리 대비 이득이 불확실 |
| GRPO / PPO 본격 도입 | 11일 내 안정화 난이도가 높고, AIMO-1 팀도 RL에서 이득을 못 봄. **[A]~[D]가 모두 끝나고 3일 이상 남을 때만** 착수 |
| 프롬프트 추가 튜닝 | B1이 B0보다 낮았음(3.4). 이미 수확이 끝난 영역 |
| 리더보드 점수 기반 반복 제출 튜닝 | Public은 30%에 불과하고, 규칙상 probing은 부정행위 |

## 9. 발표 평가 50%를 위한 준비

최종 수상은 **모델 성능 50% + 발표 평가 50%**다. 리더보드 1~2pp보다 아래 셋이 배점상 더 크다.

1. **ablation 표**: base → +추출기 수리 → +answer-only SFT → +verified-CoT SFT → +maj@k → +GenSelect. 6.2의 대조군 5종이 그대로 이 표가 된다. **특히 "answer-only SFT vs verified-CoT SFT" 비교는 우리 방법론의 정당성을 증명하는 핵심 슬라이드다.**
2. **"왜 AIMO를 그대로 못 따라 했는가"의 정량적 서술**: TIR 금지 → +11.9pp 상실 → RFT + GenSelect로 대체 → 실제 회수 폭. 제약을 이해하고 설계를 바꿨다는 것 자체가 방법론의 우수성이다.
3. **재현성 증거**: 동일 seed 2회 재현, 전 산출물 SHA-256, 실험 registry. 규칙상 재현 검증 실패는 수상 취소 사유이기도 하다.
4. **데이터 품질 감사**: 대회 측 627행 제외 목록을 역공학해 "이미지 필터가 아니라 라벨 신뢰도 필터"임을 보이고(2.4), 같은 기준을 RFT `c` 값으로 canonical에 확장해 **잔존 파손·오답 비율의 하한을 숫자로 제시**한다(5.2). 주최 측이 준 파일을 그대로 쓰지 않고 성격을 검증했다는 점이 데이터 이해도를 보여주는 대목이다.

3.5의 "토큰 상한 도달 시 97% 오답", 2.4의 "제외 목록의 43%는 이미지 문제가 아니었다" 같은 **실측 발견 하나**가 잘 만든 슬라이드에서는 모델 개선분보다 강한 인상을 준다. 분석 과정을 버리지 말고 기록할 것.
